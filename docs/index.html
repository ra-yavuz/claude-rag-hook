ra-yavuz / claude-rag-hook

claude-rag-hook v0.1.0

Type rag: <question> in Claude Code. Get a retrieval-augmented answer.

A UserPromptSubmit hook for Anthropic's Claude Code that does keyword-triggered local RAG. Type the trigger; the hook walks up from cwd, finds an indexed folder, embeds the query, retrieves the top-K relevant chunks from a per-folder LanceDB index, and prepends them to the prompt as a context block. Claude reads the enriched prompt and answers normally. Prompts that do not start with the trigger pass through untouched, so there is zero token overhead on non-RAG turns. Cheap, deterministic, local-first.

Open source under the MIT License. Provided as is, no warranty: read the full disclaimer before installing. RAG retrieves text from local files and sends it to Anthropic when retrieval triggers.

How it feels

> rag: where do we handle auth tokens? [hook resolves index at .claude-rag-index/] [hook embeds query, retrieves top-5 chunks, prepends to prompt] <context> --- src/auth/middleware.go:42-78 (code) --- func authenticate(r *http.Request) (*User, error) { ... } --- README.md:54-72 (prose) --- ## Auth flow ... </context> (your original question reaches Claude with the context block above it)

A prompt that does not start with the trigger keyword (rag:, /rag, or rag@<tag>:) falls through to Claude Code unchanged. Zero token overhead on non-RAG turns, no extra tool definitions in every system prompt.

Why a hook, not an MCP server?

Three local-RAG-for-Claude-Code projects already exist on GitHub: shinpr/mcp-local-rag, ItMeDiaTech/rag-cli, zilliztech/claude-context. All three are MCP-driven (model decides when to retrieve) or full plugins (always inject). None of them implement a simple keyword-triggered hook. The hook shape is genuinely different:

  1. Cheapest option per turn. No tool-call round trip; no context injection on prompts that do not need RAG; no MCP tool definitions bloating every system prompt.
  2. Deterministic. The user sees the keyword, types it, gets retrieval. No "why didn't the model use the tool that time" debugging.
  3. Composable with model-decides RAG. Power users can install both: keyword-trigger for the fast known-need lookups; MCP server for the rare "Claude noticed I might want to look something up" cases.

The only architectural cost is asking the user to learn the keyword. That cost is small and the keyword is configurable.

Install

apt (Debian / Ubuntu, recommended). One line. Sets up the signed apt repo if not already added, refreshes the package index, and installs claude-rag-hook. Idempotent, safe to re-run: 
sudo bash -c 'set -e; install -m 0755 -d /etc/apt/keyrings && curl -fsSL https://ra-yavuz.github.io/apt/pubkey.gpg -o /etc/apt/keyrings/ra-yavuz.gpg && echo "deb [signed-by=/etc/apt/keyrings/ra-yavuz.gpg] https://ra-yavuz.github.io/apt stable main" > /etc/apt/sources.list.d/ra-yavuz.list && apt update && apt install -y claude-rag-hook'

The apt package depends on python3-yaml, python3-numpy, and python3-pathspec (all in the Debian / Ubuntu archive). The default fastembed embedder is not packaged for Debian; install it via pip after the apt install: pip install --user fastembed lancedb pyarrow. Or pick a different embedder backend in ~/.config/claude-rag-hook/config.yaml (OpenAI-compatible, hydra-llm).

pip (any platform with Python 3.10+). 
pip install --user 'claude-rag-hook[fastembed]'
On macOS / WSL2 / a non-Debian Linux this is the simpler path. Pulls the fastembed embedder, LanceDB, and pyarrow as a single resolvable bundle.

Wire it into Claude Code

claude-rag-hook install        # adds a UserPromptSubmit entry to ~/.claude/settings.json

The installer modifies ~/.claude/settings.json automatically with a clear backup at settings.json.bak.<timestamp>. The entry is tagged "name": "claude-rag-hook" so claude-rag-hook uninstall finds and removes only our entry, leaving any other hooks you have installed alone.

What it adds to settings.json 
{
  "hooks": {
    "UserPromptSubmit": [
      {
        "name": "claude-rag-hook",
        "command": "claude-rag-hook hook",
        "description": "Keyword-triggered local RAG: 'rag: <q>' prepends retrieved chunks."
      }
    ]
  }
}

Index a folder

cd ~/projects/your-app
claude-rag-hook index .          # walk + chunk + embed + store at .claude-rag-index/
claude-rag-hook ls               # list every folder you have indexed
claude-rag-hook query "where do we handle auth?"   # sanity-check retrieval, no Claude

# Re-running index . is incremental: only changed files re-embed.
# Force a full rebuild:
claude-rag-hook index . --full

The walker respects .gitignore, skips a builtin blacklist (node_modules, .venv, target, lockfiles, binaries, archives, media, weights, files >1 MB), and classifies every file as code or prose by extension first, then by canonical basename, then by shebang sniff. The chunker is line-aware (1500 chars target, 200 overlap, never splits mid-line).

Trigger forms

TriggerEffect
rag: <text>Retrieve from the index in or above cwd. Default form.
/rag <text>Same, slash-command flavour. Useful if you also use /-prefixed commands in Claude Code.
rag <text>Lax form, off by default. Toggle in config; risk of accidental triggers on prompts that start with the word "rag".
rag@<tag>: <text>Federate retrieval across every store carrying <tag>. Tag stores at index time with --tag work.
rag@all: <text>Federate across every registered store, regardless of tag.

Federation uses Reciprocal Rank Fusion (k=60): the query is searched against every relevant index, and the lists are fused so the chunks Claude sees are the best across all of them, not the top-K of one.

Configuration

Single YAML file at ~/.config/claude-rag-hook/config.yaml. Defaults are inlined in the binary; a missing file is not an error. To override only what you need:

triggers:
  - "rag:"
  - "/rag"
top_k: 5
embedder:
  kind: fastembed
  model: nomic-embed-text-v1.5
  # Or for an OpenAI-compatible local server:
  # kind: openai-compatible
  # base_url: http://127.0.0.1:19080
  # query_prefix: "search_query: "
  # document_prefix: "search_document: "
  # Or to reuse a hydra-llm embedder by id:
  # kind: hydra-llm
  # hydra_id: nomic-embed-text
chunking:
  target_chars: 1500
  overlap_chars: 200
walker:
  max_file_size_mb: 1
  respect_gitignore: true
daemon:
  idle_ttl_seconds: 1800
  enabled: true

Read or set keys from the CLI: claude-rag-hook config embedder.kind hydra-llm.

What you actually get

Keyword-triggered, deterministic

Type rag:, get retrieval. Don't, and the hook is a no-op. No model-decides debugging, no MCP tool definitions in every system prompt, no per-turn round trip on prompts that do not need RAG.

Per-folder LanceDB index

Stored at <folder>/.claude-rag-index/ alongside your code. Copy a project to another machine, the index comes along. Re-running index . is incremental: only changed files re-embed.

Pluggable embedders

Default fastembed with nomic-embed-text-v1.5 (no HF token needed). Or swap in any OpenAI-compatible /v1/embeddings server, or reuse a hydra-llm embedder by id.

Warm embedder daemon

A small per-user process keeps the embedder loaded behind a ~/.cache/claude-rag-hook/embedder.sock Unix domain socket. First triggered turn pays cold-start; subsequent turns are sub-second. Idles out after 30 min by default.

Cross-folder federation

rag@work: <q> retrieves across every store you tagged work. rag@all: <q> hits every registered store. Reciprocal Rank Fusion picks the best chunks across the merged lists.

hydra-llm interop

If you already run hydra-llm for local LLMs and RAG, claude-rag-hook reuses its embedder catalog and reads its .hydra-index/ stores transparently. No re-indexing.

Code / prose classifier

Each file is classified by extension, then by canonical basename, then by shebang sniff. Line-aware overlap chunker (1500 chars, 200 overlap, never splits mid-line).

Safe, reversible install

install patches ~/.claude/settings.json with a timestamped backup. uninstall removes only the name: claude-rag-hook entry, leaving other hooks alone. --dry-run prints the change without writing.

Hook protocol

Claude Code's UserPromptSubmit hook contract: stdin receives a JSON envelope with the user's prompt and conversation metadata; stdout becomes context that Claude sees; exit code 0 means proceed. The hook is fail-soft: any error is logged on stderr and exits 0 so the user still gets a response. Non-trigger prompts produce no stdout at all.

stdin:  {"prompt": "rag: ...", "cwd": "/path/to/project"}
stdout: <context>
        --- file:lines (kind) ---
        ...chunk text...
        </context>
exit:   0
What it indexes (and what it skips)

Walks the folder, respecting .gitignore via pathspec. Always skips: .git, node_modules, bower_components, .venv, venv, __pycache__, .pytest_cache, .mypy_cache, .ruff_cache, target, build, dist, out, .next, .nuxt, .gradle, .idea, .vscode, lockfiles (package-lock.json, yarn.lock, pnpm-lock.yaml, poetry.lock, Cargo.lock, composer.lock), binaries, archives, media, model weights (.gguf, .safetensors, .onnx), and any file larger than 1 MB. Each surviving file is classified code or prose; the rest are skipped.

Pairs with hydra-llm

hydra-llm is the sibling project for running local LLMs with RAG built in. claude-rag-hook integrates two ways:

  • Embedder reuse. Set embedder.kind: hydra-llm and embedder.hydra_id: <id>. The hook reads ~/.config/hydra-llm/embedders.yaml, asks hydra-llm rag info <id> for the runtime port, and calls /v1/embeddings. The hook never starts or stops the container; you run hydra-llm normally.
  • Store reuse. If a folder has a .hydra-index/ instead of (or in addition to) a .claude-rag-index/, claude-rag-hook reads it transparently. hydra-llm users do not have to re-index for Claude Code.

Both are optional. Standalone use is the default. The interop exists so the two tools cooperate cleanly for users who run both.

Privacy

  • The hook reads files inside any folder you index and stores chunked text plus embeddings of those files at <folder>/.claude-rag-index/.
  • The hook injects retrieved chunks into the prompt that is sent to Anthropic. Indexed material is shipped to Claude when retrieval triggers. Audit what you index. Indexes never leave your machine on their own, but retrieval results do, because that is the entire point.
  • The warm embedder daemon runs as your user. The socket lives under ~/.cache/claude-rag-hook/ with mode 0700 / 0600.
  • No telemetry. No analytics. No auto-update calls. The CLI exits without phoning home.

Platform support

Linux is the primary target (Debian, Ubuntu, Fedora, Arch). macOS and WSL2 work via pip install; the warm daemon's Unix domain socket works on macOS too. Anywhere Claude Code itself runs, the hook can run alongside it.
